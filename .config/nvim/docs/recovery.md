# Восстановление после сбоя

При первом запуске Neovim после аварии появится предложение восстановить
сохранённые вкладки. Если при аварии работало несколько экземпляров, их вкладки
объединяются в одном Neovim с сохранением разделения окон, рабочих каталогов,
файлов и позиций курсора. Уже открытые при запуске файлы остаются в своих вкладках.
Если другой процесс Neovim этого пользователя ещё работает, вопрос не появляется.

Выбор «Позже» оставляет снимки для следующего запуска или `:SessionRecover`.
Выбор «Удалить снимки» явно удаляет предложенные снимки.
При обычном выходе текущий экземпляр удаляет только свой снимок.

Снимок обновляется через 300 мс после изменения вкладок/окон и каждые 5 секунд,
включая текст терминальных буферов. `:SessionSave` сохраняет его сразу.
Сбой может потерять изменения с момента последнего снимка.
Для уже открытых экземпляров включи модуль без перезапуска:

```vim
:lua require('config.recovery').setup()
```

## Терминалы и Codex

Восстановление открывает новые оболочки в сохранённых каталогах и выводит в них
сохранённую историю терминалов. Видны команды `codex resume <ID>`, которые успели
попасть в снимок. Сохраняется текст, доступный в терминальном буфере Neovim:
экран и scrollback, обычно до 10 000 строк. Это история вывода; shell history,
сохраняемый самой оболочкой, не подменяется. Старые команды не исполняются.
Восстанавливаются также скрытые терминальные слоты, панель и агентские терминалы.

Процессы после перезагрузки завершены. Разговор Codex продолжает команда
`codex resume <ID>` из сохранённого текста. В восстановленном терминале можно
выполнить `:SessionResume`: она запускает `codex resume --all` для выбора разговора.
Codex автоматически при восстановлении не запускается.

Для ещё работающего Codex модуль дополнительно сохраняет ID из имён открытых
rollout-файлов процессов, принадлежащих этому терминалу. Их команды выводятся
как кандидаты. Общий сервер Codex и недоступные дескрипторы могут мешать точному
соответствию: ID может отсутствовать или кандидатов может быть несколько.
Выбор `codex resume --all` остаётся доступен даже если авария произошла раньше,
чем Codex напечатал команду продолжения.

История разговоров хранится самим Codex отдельно; снимок Neovim её не заменяет.
См. [официальную документацию Codex](https://learn.chatgpt.com/docs/codex/cli).

## Хранение и ограничения

Личные снимки находятся в `stdpath('state')/crash-sessions` (обычно
`~/.local/state/nvim/crash-sessions`). Каталог создаётся с правами 0700,
JSON-снимки с правами 0600 и заменяются атомарно с записью на диск.
Идентификатор загрузки Linux и время запуска процесса защищают от повторного PID.
Повреждённые снимки сохраняются для ручного разбора, с уведомлением об ошибке.
Headless/RPC-запуски восстановления не предлагают и снимков не создают.

Сохраняются несохранённые обычные и безымянные буферы. Разные несохранённые копии
одного файла из разных экземпляров открываются отдельно; дополнительная копия
безымянная, исходный путь доступен через `:echo b:session_original_path`.
Встроенное автосохранение при сборке вкладок временно приостанавливается.
Плавающие окна не сохраняются; панели плагинов открываются как заглушки.

Проверка из корня репозитория:

```bash
python3 -m unittest discover -s tests -p 'test_recovery.py' -v
```
